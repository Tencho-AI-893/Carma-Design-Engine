# 「要確認」「保留」になった行を手動で解消する手順

対象: SM.Carma 会員データ取り込みモジュール（`server/member-import/`）

このモジュールは、少しでも自動判定に自信が持てない行は、
**絶対に自動でIDを確定させず、必ず人の目で確認するように**設計してある。
そのため取り込み後、以下の3種類が「要確認・保留」として残ることがある。
これは異常ではなく、正しく安全側に倒れている状態。

| 判定 | 意味 |
|---|---|
| 電話番号なし（要確認） | 電話番号が空欄で、氏名の候補も見つからなかった行 |
| 氏名一致候補あり・保留 | 電話番号が一致しなかった（または空欄）が、氏名だけ既存会員と一致した行 |
| 要確認（処理済み後にデータ変更検知） | 一度処理した後に、元のスプレッドシートの内容が書き換わっていた行 |

---

## 確認する方法

1. 管理画面（`/form-import`）の「② ドライラン」または「⑤最新ログ確認」を開く。
2. 一覧の「判定」列で、上の3種類のいずれかになっている行を探す。
3. 「理由」列に、なぜ保留になったか（候補の会員IDなど）が書かれている。

コマンドで直接見たい場合:

```bash
curl -X POST http://localhost:PORT番号/form-import/dry-run
```

`rows` の中の `判定` が上記3種類の行を確認する。

---

## 解消の流れ（1件ずつ、必ず目視で判断する）

### ケース1: 「氏名一致候補あり・保留」

「理由」欄に書かれている候補の会員ID（例: `M-0003`）を確認し、

1. その会員IDの既存情報（電話番号・来店履歴など）を確認する。
2. 本当に同一人物だと確信できる場合のみ:
   - 既存の会員台帳（実際の会員DB）側で、その会員の電話番号情報を
     手動で更新する（今回の新しい電話番号を反映する等）、
     もしくは今回の来店を既存会員IDに紐付けて記録する。
3. 別人だと分かった場合、または確信が持てない場合:
   - 何もせず、新規会員として別途登録する（このモジュールでは自動発行しない
     ので、既存の新規会員登録の手順で対応する）。

**絶対にしないこと**: 「たぶん同じ人だろう」で自動ツールに統合させること。
このモジュールが自動でやらない一番の理由がここにある。判断は必ず人が行う。

### ケース2: 「電話番号なし（要確認）」

1. 可能であれば、本人に電話番号を確認する（LINE・来店時のヒアリング等）。
2. 電話番号が判明したら、フォームの回答（元データ）を修正するか、
   会員登録時に正しい電話番号で改めて登録する。
3. 電話番号がどうしても分からない場合は、暫定的に新規会員として登録し、
   後日電話番号が判明した時点で名寄せをやり直す。

### ケース3: 「要確認（処理済み後にデータ変更検知）」

これは「一度取り込んだ後、元のスプレッドシートの内容が変わった」ことを
検知した場合に出る。既存の判定結果を自動で上書きしないようにするための
安全装置なので、以下を確認する。

1. なぜ元データが変わったのか確認する（本人からの修正依頼か、誤操作か）。
2. 意図した修正であれば、その行の取り込み進捗（`data/import-state.json`）を
   開発担当に依頼して該当行だけ手動でリセットしてもらい、再度取り込む。
3. 誤操作であれば、元データを元に戻す。

---

## 覚えておいてほしいこと

- 「要確認・保留」が0件にならなくても、取り込み処理自体は正常。
  これは**安全に倒すために意図的に残っているもの**。
- 迷ったら、統合せず「新規」として扱う方が安全（後から統合はできるが、
  誤って統合した後に分離するのは非常に難しいため）。
