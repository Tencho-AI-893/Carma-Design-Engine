# データが壊れた・おかしくなったときの復元手順

対象: SM.Carma 会員データ取り込みモジュール（`server/member-import/`）

小学生でも迷わないように、上から順番にそのままコピペして進めれば戻せるようにしてある。

---

## まず落ち着いてやること

1. パソコンの操作を止める（それ以上クリックしない）。
2. 画面が動いている場合は、他の人にも「今データ触らんといて」と声をかける。
3. 下の手順1から順番に進める。

---

## 手順1: 今どんなバックアップがあるか確認する

ターミナル（黒い画面）を開いて、次のコマンドを1行だけ実行する。

```bash
cd server/member-import
npm run restore:list
```

こう表示される:

```
復元できるバックアップ（新しい順）:
  20260926_093545_208
  20260926_083012_501
  ...
```

一番上（一番新しい）のが、直近の状態。基本的には「事故が起きる直前」の
一番新しいものを選べば良い。

---

## 手順2: 復元する（コマンド1発）

手順1で確認した名前（例: `20260926_093545_208`）を使って、次のコマンドを実行する。

```bash
npm run restore -- 20260926_093545_208
```

※ `20260926_093545_208` の部分は、実際に確認した名前に置き換えること。

成功すると、こう表示される:

```
復元が完了しました。
  復元元: .../data/backups/20260926_093545_208
  復元前の状態は念のためここに保存されています: .../data/backups/<新しい日時>
```

**「復元前の状態」も自動で保存されている**ので、もし復元先を間違えても、
さらにそこから元に戻すことができる（二重の安全網）。

---

## 手順3: 元に戻ったか確認する

管理画面（`/form-import`）を開き直し、「④検証」または以下のコマンドで
データが正常か確認する。

```bash
curl -X GET http://localhost:PORT番号/form-import/validate
```

`"ok": true` と出れば問題なし。`"ok": false` と出た場合は、
[要確認リストの解消フロー](./manual-merge.md) の該当箇所を読むか、
店長（開発担当）に「復元したけどvalidateがfalseになる」と伝える。

---

## よくある質問

**Q. どのバックアップを選べばいいか分からない**
A. 迷ったら一番新しい日時のものを選ぶ。それでもおかしければ、
　 1つ前の日時のものを試す（`npm run restore:list` で全部見える）。

**Q. 復元をやり直したい**
A. 何度でもやり直せる。復元するたびに「復元前スナップショット」が
　 自動で追加されていくので、データが消えることはない。

**Q. バックアップが1件も無いと言われた**
A. `data/backups/` フォルダの場所が正しいか、環境変数 `MM_BACKUP_DIR` が
　 本番用に設定されているかを確認する。分からなければ開発担当に連絡する。
