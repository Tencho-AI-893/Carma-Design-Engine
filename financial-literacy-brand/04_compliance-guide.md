# 04. 法令に配慮した表現ガイド

> **重要な前提**
> 本ファイルは、発信を続けるための**社内向け表現ガイド**であり、法的助言ではありません。
> 実際の事業設計・商品設計・広告表現は、必ず弁護士等の専門家に確認してください。
> 制度は変わります。制度変更時にこのファイルを更新し、変更履歴を残してください。

---

## 1. 基本スタンス

このブランドは**投資助言業ではない**。
だから、次の線を絶対に越えない。

| 越えない線 | 意味 |
|---|---|
| 個別・具体の売買助言をしない | 「あなたは今◯◯を買うべき」と言わない |
| 助言の対価を受け取らない | 有料商品は「判断の仕組み」であり、銘柄推奨ではない |
| 一任運用をしない | 他人の資金を預かって運用しない |
| 断定的判断の提供をしない | 「必ず上がる」等の表現を使わない |

**設計思想**：
線ギリギリを狙わない。**線から十分に離れた場所で成立するビジネスモデル**を作る。
これは規制回避ではなく、ブランドの理念（＝自分で判断できる力を育てる）と完全に一致する。

## 2. 意識すべき主な法令・ルール（概観）

| 領域 | 何が問題になりうるか | 実務上の対処 |
|---|---|---|
| **金融商品取引法**（投資助言・代理業） | 対価を得て、有価証券の価値等について助言すると登録が必要になりうる | 個別銘柄の売買推奨をしない／有料商品は「自分の運用記録」と「判断の枠組み」に限定する |
| **同法（断定的判断の提供）** | 「必ず儲かる」等の断定 | 言い換え辞書（`02`）を徹底 |
| **景品表示法**（優良誤認・有利誤認） | 実態より著しく良く見せる表示 | 実績は根拠と条件を併記。損失も同時に表示 |
| **ステルスマーケティング規制** | 広告なのに広告と分からない表示 | PR・アフィリエイトは冒頭に明示 |
| **特定商取引法** | 有料商品の表示義務 | 販売ページに事業者表示・返金条件等を明記 |
| **著作権法** | チャート・記事・書籍の引用 | 出典明記・引用の要件を守る／画像は権利確認 |
| **個人情報保護法** | メールアドレス等を、方針を示さずに取得・利用する | 取得前に利用目的を公表する／目的外に使わない／問い合わせ窓口を置く |
| **暗号資産関連** | 交換業でない者の勧誘的表現 | 取引所紹介はアフィリエイト表記を明示 |

> 特に注意：**「有料」＋「個別銘柄の売買タイミング」の組み合わせ**が最もリスクが高い。
> このブランドは、有料商品からこの組み合わせを構造的に排除する（→ `07_monetization.md`）。

## 3. 表現セルフチェック（公開前に必ず）

公開前に、この6問すべてに「はい」と答えられるか確認する。

- [ ] 未来の値動きを**断定**していないか
- [ ] 「必ず」「絶対」「確実」「保証」を使っていないか
- [ ] 読者に**特定商品の売買を指示する形**になっていないか
- [ ] 実績を出す場合、**損失・条件・期間**も併記しているか
- [ ] PR・アフィリエイト・提供がある場合、**冒頭で**明示しているか
- [ ] 末尾に**免責文**を入れたか

## 4. 免責文テンプレート

### 4-1. 標準版（記事・レポート末尾）

```
【免責事項】
本コンテンツは、筆者自身の学習および運用記録の公開を目的とした情報提供であり、
特定の金融商品の取得・売却を推奨するものではありません。
筆者は投資助言業者ではなく、記載内容は個人の見解です。
将来の運用成果を示唆・保証するものではありません。
投資判断は、ご自身の責任と判断において行ってください。
記載された制度・税制は執筆時点のものであり、変更される場合があります。
```

### 4-2. 短縮版（SNS投稿末尾）

```
※個人の運用記録です。推奨ではありません。投資判断はご自身の責任で。
```

### 4-3. 有料コンテンツ版

```
【本商品について】
本商品は、判断の枠組み・記録の仕組み・分析ツールを提供するものであり、
特定の銘柄や商品の売買を推奨・助言するものではありません。
本商品の利用によって、利益が生じることを保証するものではありません。
運用の結果生じた損益は、すべて利用者に帰属します。
```

### 4-4. PR・アフィリエイト表記（冒頭に配置）

```
※本記事にはプロモーションを含みます。
```

## 5. ケース別：OK / NG の判断例

| ケース | NG例 | OK例 |
|---|---|---|
| 銘柄について語る | 「MSTRは買いです」 | 「私はMSTRを検証対象として、事前に公開したルールに従い積み立てています」 |
| 利確について語る | 「今が利確のタイミングです」 | 「私のルールでは、この条件を満たしたため一部を利確しました」 |
| 実績を出す | 「+150%達成！」 | 「◯年◯月〜◯年◯月の期間で+150%。同期間の最大下落率は−60%でした」 |
| 制度を語る | 「新NISAなら絶対に増えます」 | 「新NISAは制度上こうなっています。増えるかどうかは投資先と期間によります」 |
| 有料商品を売る | 「勝てる銘柄がわかるツール」 | 「自分の判断基準を数値で管理するためのテンプレート」 |
| AIについて語る | 「AIが最適な売買を教えてくれます」 | 「AIに判断材料を整理させ、最終判断は自分で行う手順を検証しています」 |

## 5-2. 個人情報を預かる前に（メール配信・フォームを開く条件）

**このブランドにおいて、個人情報の取得は「信頼の前借り」の最上位形態である。**
商品を売ることより、コミュニティに誘うことより重い。だから順序を固定する。

### 受付を開いてよい条件（3つすべて）

- [ ] 個人情報の取り扱い方針を公開し、フォームの近くからリンクしている
- [ ] 届けるもの（月次レポート等）が、実際に発行できる状態にある
- [ ] 解除方法が、登録時点で明示されている

**1つでも欠けているあいだは、フォームを開かない。**
LPでは `data-endpoint` が空のあいだ受付欄が自動的に閉じる実装にしてある
（→ `lp/index.html`）。順序を意思ではなく仕組みで守るため。

### 取り扱い方針に最低限書くこと

| 項目 | 内容 |
|---|---|
| 取得する情報 | メールアドレス（それ以外を取得しないなら、そう書く） |
| 利用目的 | 月次レポート等の配信。**目的外には使わない**と明記する |
| 第三者提供 | しない／する場合は条件を明記 |
| 委託先 | 利用する配信サービス名を記載する |
| 保管期間・削除 | 解除時の扱いを明記 |
| 問い合わせ窓口 | 連絡手段を明記 |

> 方針の文面は、利用する配信サービスや事業形態によって必要事項が変わる。
> 公開前に専門家に確認すること。

## 6. 制度変更時の運用

金融制度（NISA・税制・暗号資産の扱い等）は変わる。
制度変更は**リスクではなくコンテンツ機会**として扱う。

1. 変更内容を一次情報（官公庁・取引所の公式発表）で確認する
2. このファイルと該当プロジェクト設計書を更新する
3. 「制度が変わったので、私はこう対応します」を記事化する
4. 過去記事は削除せず、**冒頭に注記**を追加する

> 過去記事を消さないことが、10年ブランドの条件。
> 消すと履歴が消え、履歴が消えると信頼の証拠が消える。
