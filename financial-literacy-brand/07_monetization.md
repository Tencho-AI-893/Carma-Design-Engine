# 07. 収益設計

---

## 1. 原則

> **売るのは「答え」ではなく「判断できる状態」。**

この一行が、理念・法令配慮・事業性を同時に満たす。

| 売らないもの | 売るもの |
|---|---|
| 買うべき銘柄 | 自分で銘柄を評価する枠組み |
| 売買のタイミング | 自分の売買ルールを設計する手順 |
| 未来の予測 | 予測に頼らない運用の仕組み |
| 情報 | 判断の再現性 |

**「答えを売らない」は制約ではなく、参入障壁である。**
答えを売るビジネスは、答えが外れた瞬間に終わる。
仕組みを売るビジネスは、相場が何であっても続く。

## 2. 商品ラインナップ設計

| 段階 | 商品 | 内容 | 価格帯の考え方 |
|---|---|---|---|
| **0. 無料** | 記録・教養 | 月次レポート、思考法、失敗談 | 0円（信頼の獲得） |
| **1. 入口** | 実践マニュアル / ケーススタディ | 記録を体系化したPDF・note | 単発・低価格（心理的障壁を下げる） |
| **2. 道具** | 運用テンプレート / AIプロンプト / 自動計算ツール | 実行を助ける具体物 | 単発・中価格（対価が明確） |
| **3. 環境** | ダッシュボード / 運用OS | 判断を継続的に管理する仕組み | 継続課金（価値が継続する） |
| **4. 伴走** | コミュニティ | 実践の場・記録の共有 | 継続課金（最も高LTV） |

> 価格の**具体的な金額はここに書かない**。市場と自分の提供価値が決めるもので、
> 設計書に固定すると値付けが硬直するため。決めたら `templates/decision-log.md` に理由付きで記録する。

## 3. 商品化してよいか判定する5問

新しい有料商品を作る前に、必ず通す。

- [ ] これは「答え」ではなく「仕組み」か
- [ ] 買った人が、**自分で判断できるようになる**か
- [ ] 特定銘柄の売買推奨を含まないか（→ `04`）
- [ ] 無料コンテンツの読者が、**買わなくても損しない**設計か
- [ ] 3年後も価値が残るか（相場依存でないか）

**4問目が特に重要。**
無料部分をわざと不完全にして有料に誘導する設計は、このブランドでは禁止。
無料は無料で完結させる。有料は「もっと楽に、確実に実行したい人」のための時短と仕組み。

## 4. 段階設計（無理のない収益化順序）

```
Year 1  ：「信頼の前借り」をしない。道具の対価のみ受け取る（下記 §4-2）
          → ここで高額商品を売ると、ブランドが「情報商材」に見える

Year 2  ：段階1〜2（マニュアル・テンプレート）を出す
          → 12ヶ月の記録が、商品の信頼性を担保する

Year 3  ：段階3（ダッシュボード・運用OS）
          → Project 02（AI）の検証結果が原材料になる

Year 4〜：段階4（コミュニティ）
          → 4年間の記録があって初めて、伴走に説得力が出る
```

**Year 1 で売らないことが、Year 4 の価格を決める。**
この順序を守れるかどうかが、10年ブランドと単発ビジネスの分岐点。

## 4-2. 禁止するのは「収益化」ではなく「信頼の前借り」（→ `11_dialectic.md` 対立3）

収益ゼロで1年走る設計は、「継続が最優先」という原則と矛盾する。
純度を守って燃え尽きたブランドに、価値は残らない。**線を引き直す。**

| Year 1 に売ってよい | Year 1 に売ってはいけない |
|---|---|
| 自分が**実際に使っている**道具（テンプレート等） | まだ実績のない「コミュニティ」「伴走」 |
| 実費・低価格での配布 | 高額商品 |
| 制作コストが対価と明確に釣り合うもの | 将来の成果を期待させる商品 |
| 使っている商品のアフィリエイト（PR明示） | 自分が使っていない商品の紹介 |

### 判定基準（一行）

> **「これは、まだ存在しない信頼を担保に売っているか？」**

- **道具** ＝ いま存在する労働の対価 → 売ってよい
- **伴走** ＝ まだ存在しない実績の対価 → 売ってはいけない

これで、ブランドの純度と継続の資金を、どちらも失わない。

## 4-3. 「答えの形をした仕組み」（→ `11_dialectic.md` 対立4）

「自分で判断できるようになりたい」と本気で思う人は市場の少数派。
理念的に正しい商品が、正しいがゆえに売れないリスクがある。

**入口（買う理由）と中身（使って得るもの）を、別の層として設計する。**

```
   入口（買う理由）           中身（使って得るもの）
   ─────────────            ─────────────────
   具体的・即物的        →      普遍的・再現的
   「15項目チェックリスト」  →   「判断の型が身につく」
   「利確判定シート」       →   「感情で売らなくなる」
   「AIプロンプト20本」     →   「AIに依存しない使い方」
```

**人は答えを買い、仕組みを使う。**

これは欺瞞ではない。「学ぶ意欲のある人だけどうぞ」という設計こそ、教育の放棄である。
答えの顔をして入口に立ち、中で判断力を渡す。

> **商品名に「考え方」「本質」「思考法」と付けない。**
> 「チェックリスト」「テンプレート」「シート」と付ける。
> **中身は変えない。名前だけを具体にする。**

## 5. 収益源の分散

一本足はブランドを歪める。次の配分を目安にする。

| 収益源 | 目安 | 備考 |
|---|---|---|
| 自社商品（テンプレ・ツール・コミュニティ） | 60〜70% | 主軸。理念と一致 |
| 広告・アドセンス | 10〜20% | 依存すると PV至上主義に傾く |
| アフィリエイト | 10〜20% | 必ず冒頭にPR表記（→ `04`） |
| 企業案件・講演・執筆 | 10〜20% | ブランド価値の外部証明にもなる |

### 受けない案件（事前に決めておく）

- 断定的な表現を求められる案件
- 実績を誇張する表現を求められる案件
- 自分が使っていない商品の紹介
- 「初心者向け」を装った高リスク商品の紹介

**断る基準を事前に決めておくことが、判断を守る唯一の方法。**
これは Project 01 の「事前公開ルール」と、まったく同じ構造。
