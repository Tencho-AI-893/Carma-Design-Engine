# Project 01：BTCサイクル積立プロジェクト

**ステータス**：稼働中
**位置づけ**：ブランド「金融リテラシー＝人として」の第1ケーススタディ

> ※これは金融リテラシーを学ぶためのケーススタディであり、
> 特定銘柄の購入を推奨するものではありません。

---

## 1. このプロジェクトが答えようとしている問い

**「一般の実践者が、事前にルールを決め、4年間それを守り切れるのか。そのとき何が起きるのか」**

Bitcoinの値動きを当てることが目的ではない。
**ルールを持つ人と持たない人の差**を、4年間の実記録で示すことが目的。

だから、このプロジェクトは価格が上がっても下がっても成立する。
**これが、相場に依存しないコンテンツ設計の核心。**

---

## 2. 検証内容

- Bitcoinの4年サイクルという**仮説**を検証する
- 新NISAを活用する
- BTC関連株（MSTR・メタプラネット）を積み立てる
- AIを活用した利確・リスク管理を検証する
- 4年間の運用記録を公開する

---

## 3. 仮説（事前公開）

```markdown
### 仮説 H-001：4年サイクル仮説
- 内容：Bitcoinの価格には、供給イベントを起点とする約4年周期の
        上昇・下落サイクルが存在するのではないか
- 根拠：（過去サイクルの観測／供給構造／記入）
- 反証条件：★必ず記入する
        例）サイクル起点から◯ヶ月経過しても◯◯が観測されない場合、
            この仮説は現時点で機能していないと判断する
- 検証期間：4年（YYYY/MM 〜 YYYY/MM）
- この仮説に配分する資金上限：総金融資産の ◯◯％
- 公開日：YYYY-MM-DD
```

> **反証条件は必ず埋めること。** 反証条件のない仮説は、このブランドでは公開しない（→ `03`）。
> 反証条件を書く行為そのものが、最高の金融リテラシー教材になる。

### 4-2. 積立ルール

| 項目 | 内容 |
|---|---|

### 4-3. 利確ルール ★このプロジェクト最大の急所

> **不変層の原則：出口を決めずに入らない**（→ `03_verification-protocol.md` §2-2）

### 4-6. 記入例（架空・推奨する数値ではありません）

> **この例は「どこまで具体的に書けば事前公開ルールとして機能するか」を示すためのものです。**
> 記載した数値は架空であり、特定の資産配分・売買を推奨するものではありません。
> 実際の数値は、ご自身の収入・支出・家族構成・リスク許容度から決めてください。

```markdown
### 仮説 H-001（記入例）
- 内容：Bitcoinの価格には、供給イベントを起点とする約4年周期の
        上昇・下落サイクルが存在するのではないか
- 根拠：過去3回のサイクルで、供給イベントから12〜18ヶ月後に高値圏、
        その後12〜14ヶ月かけて大幅下落という形が観測された（n=3、統計的には極めて少ない）
- 反証条件：供給イベントから24ヶ月を経過しても、直前サイクル高値を
            一度も上回らなかった場合、この仮説は現時点で機能していないと判断する
- 検証期間：4年
- この仮説に配分する資金上限：総金融資産の 10％
- 公開日：YYYY-MM-DD
```

| ルール | 記入例 |
|---|---|
| 配分上限（対総金融資産） | 10％（超えたら積立を停止し、リバランスする） |
| 生活防衛資金 | 生活費12ヶ月分。ここには絶対に手をつけない |
| 追加入金の上限（月） | 手取りの5％まで |
| レバレッジ | 使用しない |
| 積立の頻度 | 毎月第1営業日に定額 |
| 下落したとき | 金額を変えない（狼狽増額も減額もしない） |
| 急騰したとき | 金額を変えない |
| **利確の判定** | 毎月1回、第1営業日にのみ判定する（それ以外の日は判断しない） |
| **利確条件** | 供給イベントから18ヶ月経過以降、評価益率が+200％を超えた月に発動 |
| **1回の利確比率** | 保有の20％。条件を満たすたびに繰り返す（一括利確はしない） |
| **利確資金の行き先** | 全額を現金化し、生活防衛資金の外側に置く（再投入しない） |
| 最大許容ドローダウン | −70％。超えても売らないが、積立額を半分にして記録を残す |
| 停止条件 | 収入が3ヶ月連続で2割以上減った場合／反証条件に該当した場合 |
| 例外条項 | 例外を認めるのは制度変更時のみ。実行前に理由を公開する |

> **記入例を読むときの注意**
> 数値そのものより、**「いつ判断するか」を固定していること**に注目してください。
> 「毎月第1営業日にのみ判定する」と決めておくと、値動きを見て衝動的に売買する余地が消えます。
> 出口ルールの本質は、水準の設定ではなく**判断の頻度を減らすこと**にあります。

## 5. AI活用の検証範囲

**原則：AIは判断材料を整理する。最終判断は必ず人間が行う。**

| AIに任せる | 人間が行う |
|---|---|
| データの収集・整理 | 仮説の設定 |
| ルール条件の充足チェック | ルールの設計・変更 |
| シナリオの列挙 | 資金配分の決定 |
| 感情の言語化サポート | 最終的な売買判断 |
| レポートの下書き | 公開する内容の責任 |

**検証テーマ例**：
- AIに「利確条件を満たしたか」を毎月チェックさせる仕組みは機能するか
- AIに反対意見（自分の判断への反論）を出させると、判断は改善するか
- AIの提案に従いたくなる心理は、どこで危険になるか ★最も教材価値が高い

> AI活用の失敗も必ず公開する。「AIに頼りすぎた」記録は、
> 2026年以降の金融リテラシーとして極めて価値が高い。

## 8. 成功の定義

このプロジェクトの成功は、**利益率では測らない**。

| 指標 | 目標 |
|---|---|
| 月次レポートの継続 | 48ヶ月、欠かさず公開 |
| ルール遵守率 | 90%以上（破った場合は必ず記録・公開） |
| 事後的なルール変更 | 0件（変更は必ず事前・理由付き） |
| 失敗の公開 | 発生したものはすべて公開 |

**利益が出ても、記録が途切れたら失敗。**
**損失が出ても、記録が48ヶ月続いたら成功。**

この定義こそが、ブランド「金融リテラシー＝人として」の証明になる。
