# 将来プロジェクト設計（Project 02 – 04）

**原則：同時に走らせるプロジェクトは最大2つ。**
プロジェクトが増えるとブランドが薄まる。Project 01 の記録が最優先。

---

## 起動条件（すべてのプロジェクト共通）

新プロジェクトは、次の3条件を満たすまで開始しない。

1. Project 01 の月次レポートが**12回以上**連続で公開されている
2. 既存プロジェクトの記録が滞っていない
3. 新プロジェクトの**事前公開ルールが書き切れている**（→ `03`）

---

## Project 02：AI資産管理プロジェクト

**推奨開始時期**：Project 01 開始から12〜18ヶ月後

### 内容
- AIを活用した資産管理
- AIによる家計管理
- AIによる利確サポート
- AIによる意思決定補助

### このプロジェクトが答える問い
**「AIは、人の金銭判断をどこまで良くし、どこから悪くするか」**

### 検証設計の骨子

| 検証テーマ | 測り方 |
|---|---|
| AIによる家計の可視化は、支出行動を変えるか | 導入前後3ヶ月の支出構成比 |
| AIに反論させると、判断の質は上がるか | 判断ログの事後評価 |
| AIへの依存はどこで危険になるか | 「AIの提案に無批判に従った」件数 |

### 相性の良さ
このブランドは「考え方」と「仕組み」を売る。
AIはまさに**仕組み**の中核。Project 02 は有料商品（AIプロンプト・ダッシュボード）と
直結する、収益設計上も重要なプロジェクト。

### 注意点
「AIが儲けさせてくれる」という文脈に**絶対に寄せない**。
検証するのは、**判断の質**であって、収益ではない。

## Project 03：新NISA実践プロジェクト

**推奨開始時期**：Project 01 と並走可能（読者層が最も広い）

### 内容
- 新NISA制度の活用方法
- 制度の考え方
- 長期積立の実践
- 制度変更への対応

### このプロジェクトが答える問い
**「制度は、使い方を知っている人にどれだけ有利に働くか」**

### 戦略上の役割
- **新規読者の入口**（検索需要が最大）
- Project 01（BTC）はどうしても人を選ぶ。Project 03 が裾野を広げる
- 「守る」「増やす」領域の教養コンテンツと直結

### 注意点
制度解説は競合が非常に多い。**解説では勝たない。**
このブランドの差別化は、**「制度を使って、自分がどう判断したか」の記録**にある。
一般論の解説記事を量産しない。

## Project 04：経営者のお金の教養

**推奨開始時期**：ブランド認知が確立した後（3年目以降）

### 内容
- 経営と投資
- キャッシュフロー
- 資産形成
- AI経営

### このプロジェクトが答える問い
**「事業を持つ人にとって、金融リテラシーはどう違うのか」**

### 戦略上の役割
- **単価が最も高い層**にリーチする（収益の柱になりうる）
- 「稼ぐ」「残す」領域を深く扱える
- 法人・個人の両輪という、個人投資家発信では扱えないテーマ

### 注意点
税務・法務の専門性が高い領域。
**専門家との協業を前提に設計する**（自分で断定しない）。
このブランドの「実践者」ポジションは、ここでも守る。

## プロジェクト間の関係

```
        金融リテラシー＝人として
                  │
    ┌─────────────┼─────────────┬─────────────┐
    ▼             ▼             ▼             ▼
 Project 01   Project 03    Project 02    Project 04
 BTCサイクル    新NISA        AI資産管理     経営者
    │             │             │             │
  検証の核      入口・裾野     仕組みの核     収益の柱
    │             │             │             │
    └─────────────┴──────┬──────┴─────────────┘
                         ▼
              すべてが「稼ぐ・守る・増やす・使う・残す」に接続する
```

**どのプロジェクトも、単体で完結させない。**
必ず「これは金融リテラシーの5領域のどこか」を明示する。
それがブランドの一貫性を作る。
