# 失敗ログ テンプレート

> 失敗公開は、このブランドで最も価値の高いコンテンツ。
> ただし**型がないと、ただの反省文**になる。必ずこの型で書く。
>
> 3原則（`02_editorial-policy.md` §6）
> 1. 感情を書くが、感情で終わらせない
> 2. 他責にしない、しかし自責もしすぎない（構造の問題として書く）
> 3. 必ず「次のルール変更」に接続する

---

## 失敗 F-◯◯◯

| 項目 | 内容 |
|---|---|
| **日付** | YYYY-MM-DD |
| **一行で言うと** | |
| **分類** | ルール違反 / 判断ミス / 設計ミス / 情報不足 / 感情起因 / AI依存 |
| **影響** | 損失◯◯% ／ 機会損失 ／ 精神的負荷 など |

---

## 1. 何が起きたか（事実だけ）

（解釈を混ぜない。時系列で事実だけを書く）

---

## 2. そのとき何を考えていたか

（言い訳に見えても書く。ここが読者の学びになる）

---

## 3. なぜ起きたか（構造で書く）

| 層 | 原因 |
|---|---|
| 表面（行動） | |
| 中間（判断） | |
| 根本（仕組み・ルールの穴） | ★ここまで掘る |

> 「気をつける」で終わる原因分析は、必ず再発する。
> **仕組みの穴として書けたときだけ、失敗が資産になる。**

---

## 4. 感情の記録

（怖かった／悔しかった／認めたくなかった。正直に。
　ただしここで終わらない）

---

## 5. 何を変えるか

| 項目 | 内容 |
|---|---|
| 変えるルール | |
| 適用開始 | YYYY-MM-DD（原則、次四半期の頭から） |
| これで防げる理由 | |
| 防げないケース | （正直に書く。万能な対策はない） |

→ ルールを変える場合は `rule-change-log.md` にも記録する

---

## 6. 読者への一言

（同じ失敗をしないために、読者が今日できることを1つだけ）
