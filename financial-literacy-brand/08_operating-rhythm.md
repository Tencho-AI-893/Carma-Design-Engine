# 08. 運用リズム

**モチベーションに依存しない。周期に依存する。**
10年続く発信者と続かない発信者の差は、意志ではなく設計。

---

## 1. 月次サイクル

| 時期 | やること | 成果物 |
|---|---|---|
| **月初（1〜5日）** | 積立実行／ルール条件のチェック | 判断ログ |
| **月中（10〜20日）** | 教養コンテンツの執筆 | 記事1本 |
| **月末（25〜末日）** | 月次レポート作成・公開 | 月次レポート |
| **随時** | 判断・失敗が発生したら即記録 | 判断ログ／失敗ログ |

### 月次レポートを最優先にする理由

他のすべてを落としても、これだけは出す。
**48ヶ月分の連続記録が、このブランドで最も複製困難な資産だから。**

---

## 2. 四半期サイクル（3・6・9・12月）

- [ ] 仮説はまだ生きているか（反証条件に触れていないか）
- [ ] ルール遵守率の集計
- [ ] 4象限分類の集計（`03`§5）
- [ ] コンテンツ配分の確認（記録40/教養30/実務20/時事10）
- [ ] KPI レビュー（`09`）
- [ ] ルール変更の必要性を検討（変えるなら次四半期から適用）

**ルール変更は四半期の頭からしか適用しない。**
思いつきで変えないための安全装置。緊急時は例外だが、必ず「例外である」と記録する。

---

## 3. 年次サイクル

- [ ] ブランドコア（`01`）の見直し（変えないことの確認も含む）
- [ ] 年次総括記事の公開
- [ ] 次年度のプロジェクト構成の決定
- [ ] 過去記事の棚卸し（制度変更の注記追加）
- [ ] 収益構成の確認（`07`§5）

### 年次総括に必ず書く3つ

1. 今年、**守れたルール**と**破ったルール**
2. 今年、**考えが変わったこと**とその理由
3. 来年、**変えること**と**絶対に変えないこと**

---

## 4. 「出せない月」の扱い

体調・仕事・相場の急変で書けない月は必ず来る。**そのときの行動を事前に決めておく。**

| 状況 | 行動 |
|---|---|
| 執筆時間が取れない | 月次レポートを**数字と1行コメントだけ**で出す（欠かさない） |
| 大きな損失で書きたくない | それこそ最も価値ある記録。型（`templates/failure-log.md`）に沿って出す |
| 判断に迷っていて結論が出ない | 「迷っている」ことを書く（ブランドの約束＝迷いも公開する） |
| 本当に無理 | 「今月は出せません」と理由を公開する（無言の欠落を作らない） |

**沈黙だけが、このブランドで唯一の裏切り。**
何を書くかより、何があっても出すことが、信頼を作る。

---

## 5. 年間コンテンツカレンダー（雛形）

制度・季節のイベントに紐づけると、ネタ切れがなくなる。

| 月 | 定番テーマ |
|---|---|
| 1月 | 新NISA年間枠のリセット／今年の運用方針公開 |
| 2月 | 確定申告と投資（※税務は専門家確認の注記必須） |
| 3月 | 年度末・四半期レビュー |
| 4月 | 新生活とお金の教養（「稼ぐ」領域） |
| 5月 | 保険・固定費の見直し（「守る」領域） |
| 6月 | 賞与と積立（「増やす」領域） |
| 7月 | 上半期総括 |
| 8月 | お金の使い方（「使う」領域） |
| 9月 | 制度改正情報のキャッチアップ |
| 10月 | 相続・次世代（「残す」領域） |
| 11月 | 来年の制度変更の確認 |
| 12月 | 年次総括／来年の方針 |

**5領域（稼ぐ・守る・増やす・使う・残す）が年間で一周する設計。**
これで「投資だけのブランドではない」ことが、毎年自動的に証明される。
